# MKE — Medical Knowledge Engine

医学書籍PDFをローカルで登録し、書籍内の根拠を示して国家試験問題を解説するための開発基盤です。PDF登録、OCR、文字列検索、根拠付き質問回答、4択問題の選択肢別解説とExcel出力の初期版を実装しています。意味検索は未実装です。

## 確認済みの開発環境

- macOS / Intel x86_64
- Python 3.9.12
- メモリ 8 GiB
- SQLite 3.37.2（FTS5利用可能）
- Tesseract 5.5.2
- Ollama 0.40.15（`qwen2.5:3b` と `qwen2.5:latest` を確認）

Python 3.9で利用できるよう、requirements.txtでは互換性を確認したバージョンを固定しています。新しい版への更新時は、Pythonの対応範囲とIntel Mac向けwheelの有無を先に確認してください。

## ライブラリ方針

- Streamlit：ローカル画面
- PyMuPDF：PDFのページ抽出・描画
- Tesseract CLI：ページ単位のOCR。OCRmyPDF 16.10.1はPython 3.10以上が必要なため採用せず、8GBメモリでも処理量を制御しやすい構成にします。
- SQLite / FTS5：メタデータと全文検索（Python標準ライブラリ）
- Ollama HTTP API：ローカルLLM接続（追加のクライアントライブラリ不要）
- FastAPI / Uvicorn：将来のAPI境界
- openpyxl：将来のExcel出力

初期検索は専門用語の完全一致とFTS5を優先し、意味検索はローカル埋め込みモデルのメモリ・実行時間を測ってから追加します。外部APIや重いOCR/埋め込み依存を初期必須にしません。

## セットアップ

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
streamlit run app/main.py
```

`.env`は任意のローカル設定ファイルです。PDF、OCR結果、データベースなどは`storage/`に置き、Git管理対象外です。`.env`や書籍データをコミットしないでください。

## PDF登録と確認

1. アプリを起動し、サイドバーの「書籍管理」を選択します。
2. PDFと書籍名を指定し、必要に応じて著者・出版社・版・発行年を入力して登録します。
3. 登録済み書籍を選択し、PDF内部ページごとの抽出テキストを確認します。

PDF原本のコピーは `storage/original_pdfs/`、書籍とページの情報は `storage/mke.sqlite3` に保存されます。読み込み元のPDFは変更しません。同じ内容のPDFは重複登録できず、パスワード保護されたPDFには対応していません。Streamlitの標準アップロード上限は1ファイル200 MBです。

PDFの種類はページに抽出可能な文字や画像があるかに基づく**暫定判定**です。文字層付きスキャンと図版を含むテキストPDFはどちらも混在と表示され得ます。画像を含むページと文字のないページはOCR確認対象として数えますが、自動的にはOCRされません。PDF内部ページ番号は1始まりです。登録時に印刷ページ番号は設定されませんが、4択の関連ページ検索では候補を表示します。

登録するPDFは利用する権利を確認してください。`MKE_DATA_DIR`を変更する場合は、その保存先もGit管理外とし、ローカルに限定してください。バックアップ、書籍情報編集、削除は未実装です。

## ページ単位OCRと確認

サイドバーの「OCR確認」から書籍とPDF内部ページを選び、原本プレビューを表示します。横書き・縦書き・英語から言語を選んで「このページをOCR」を押し、結果を原本と照合して修正し、確認状態とともに保存してください。OCRは明示的に指定した1ページだけ実行し、同時実行を防止します。日本語の数字、医学用語、単位、記号は必ず原本と照らし合わせてください。

原本PDFとPDFから直接抽出したテキストは変更されません。OCRの生データ、単語ごとの低信頼候補、平均信頼度、修正テキストはSQLiteに保存します。再OCRでは過去のOCR結果と手動修正を残し、確認状態を未確認に戻します。修正済みテキストは最新OCR結果と異なる場合があるため、再度照合してください。信頼度は文字認識の目安であり医学的な正確性を意味しません。低信頼候補がないことも正確性の保証にはなりません。

Tesseractと日本語・英語の学習データが必要です。このMacでは `storage/tessdata/` に公式の軽量学習データを導入済みです。別環境で必要な場合は、Tesseract本体を導入した後、プロジェクトルートで以下を実行します。学習データのダウンロードのみインターネット接続が必要で、書籍は送信しません。

```bash
mkdir -p storage/tessdata
for lang in eng jpn jpn_vert; do
  curl -fL -o "storage/tessdata/$lang.traineddata" \
    "https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/$lang.traineddata"
done
```

`MKE_DATA_DIR`を変更した場合は、そのディレクトリ内の `tessdata/` に置いてください。`tessdata/` がなければTesseractの標準データを使用します。OCRの一時画像はローカルに作成し、処理終了時に削除します。異常終了時には一時ディレクトリが残ることがあります。大きすぎるページはメモリ保護のため処理を拒否します。

## 書籍内検索

サイドバーの「書籍内検索」を開き、専門用語を入力して検索します。全書籍または1冊を選べます。空白区切りの複数語は同じ文章内のAND検索です。各語は160文字以内、8語以内です。検索結果には書籍名、版、PDF内部ページ、印刷ページ（設定済みの場合）、テキストの種類、確認状態、文字列の出現回数を表示します。原本ページの表示を選んで照合できます。表示テキストは抽出・OCRまたは手動修正された文章であり、原本そのものではありません。

検索には、各ページの手動修正があれば手動修正、なければ最新OCR、どちらもなければPDF抽出テキストを使います。OCRが空でPDF抽出に文字がある場合はPDF抽出を使います。再OCR後も保存済み手動修正を優先するため、未確認の警告を見て原本と照合してください。修正やOCRの結果は次の検索時に索引へ反映されます。文章は800文字で分割し160文字重複させるため、離れた箇所の複数語は同じページでも一致しない場合があります。3文字以上の語はSQLite FTS5 trigram索引、短い語は文字列検索を用います。スコアは出現回数で、医学的確実性ではありません。

OCR未実施のスキャンや図の中の文字は検索できません。検索不能ページ数とOCR未実施ページ数を表示しますが、OCR済みでも認識漏れはあり得ます。**見つからないことは記載がない証拠ではありません。** 章・分野の絞り込みと意味検索は未実装です。現在のOllamaでは埋め込みAPIを利用できず、実測・品質検証なしに意味検索と称する機能は提供していません。

## 根拠付き質問回答

1. Ollamaを起動し、`qwen2.5:3b`を利用できる状態にします。
2. 「質問回答」画面に質問と、検索したい専門用語を入力して「根拠を検索」を押します。検索は完全一致のため、質問文全体でなく専門用語を入力してください。
3. 候補と原本を照合し、質問に関係する文章を最大3件選択して「選択した根拠で回答を生成」を押します。
4. 回答ごとの引用・書籍・版・PDF内部ページ・確認状態を、原本と照合してください。モデルが根拠不足と判断した場合は、関連する可能性のある文章をAIが抜粋することがあります。抜粋は回答の生成ではなく、関連性も未検証です。候補がない場合は表示しません。

応答の引用が選択した文章内に実在することと参照番号は検証し、検証できない応答は表示しません。抜粋時は、AIが選んだ番号に対応する原文をそのまま表示します。ただし、**引用が実在しても、引用と回答の意味の一致や医学的正確性までは自動検証できません**。OCR、抽出、解釈、書籍間の相違や見落としに注意してください。確実性の自動評価は未実装です。学習・検証用であり、診療判断には使わないでください。

書籍テキストと質問は指定したループバックIPのOllamaにのみ送ります。初期版の回答モデルは `qwen2.5:3b` または `qwen2.5:latest` です。AI生成とOCRは同時に実行しません。検索候補は上位10件までで、意味検索は使っていません。質問と回答はセッション中のみ保持し、保存機能はありません。初回生成には時間がかかる場合があります。

## 4択問題・解説

1. 「4択問題・解説」から新しい問題を登録します。問題ID、問題文、4択、模範解答、正しいもの・誤りのどちらを選ぶかを必ず指定してください。対応する正解は1つだけです。
2. 「4択の関連ページを検索」で、問題文・各選択肢に関する候補を検索します。個別検索では専門用語も指定できます。候補は検索スコア順の検索結果であり、関連性・医学的妥当性を保証しません。OCR確認状態、検索方式、書籍、版、PDF内部ページ、印刷ページ候補と原文を確認し、必要に応じて原本プレビューを開きます。
3. 選択肢ごとに使う候補を選び、「根拠状態」を指定して保存します。判定に使うには、根拠を1件以上選択し「根拠確認済み」にして、原本と照合したうえで「人による根拠確認」を完了してください。「根拠不足」「書籍間の記載矛盾」は保存できますが、解説生成の対象になりません。保存した本文・出典はスナップショットとして保持され、検索候補やチェックボックスだけでは確定根拠になりません。
4. 「保存済み確定根拠でこの選択肢を生成」または「確定根拠から4択の解説を生成」を実行します。個別・一括とも、保存済みかつ人手確認済みの確定根拠のみを使います。根拠未選択・不足・矛盾・人手未確認の選択肢は保留され、その理由を表示します。模範解答番号はAIに渡しません。既存解説・手動編集は通常の一括生成では保護され、上書きチェックを明示した場合のみ置き換わります。
5. AI判定、解説、引用、版、PDF内部ページ、根拠状態、引用検証状態、人による確認状態を確認します。引用検証の「一致」は引用文字列が確定根拠に含まれることのみを示し、引用が判定を支持するか・解説が医学的に妥当かは検証しません。生成後に原本と照合し、解説の人手確認を保存してください。Excelには既存の問題・選択肢・出典列に加えて、根拠確定・引用検証・人手確認の状態も出力します。

AIは選択肢自体の正誤を判定し、指定された設問種別に従い「設問に合う／合わない」を計算します。模範解答はAIに渡さず、保存済み4選択肢の判定と照合します。一致しない場合や未判定・判定不能がある場合は「要確認」とします。模範解答は変更しません。複数正解や「2つ選べ」の問題は未対応です。

既存データの解説は、移行時に根拠確定済み・引用確認済みとして扱いません。確定根拠を改めて保存するまで比較結果は「要確認」です。引用が実在して模範解答と一致しても医学的妥当性は未検証です。手動編集後は引用との整合性を自動検証しません。意味検索、引用の意味的支持の自動判定、複数正解、一括取込は未実装です。生成には数分かかる場合があります。

**実問題での検証結果：実用上の目標は未達です。** 大脳半球に関する4択問題では、`qwen2.5:3b` による自動生成は約131秒かかり、1選択肢を誤判定し、残る3選択肢は判定不能でした。その後、理由に「不明」などが含まれる断定を判定不能にする対策を追加しましたが、この対策後の実問題全体の品質は未検証です。同じ問題の選択肢3を `qwen2.5:latest` で試したところ、300秒でタイムアウトし、精度は比較できませんでした。結果はマシンや稼働状況によって異なります。

## テスト

```bash
python -m unittest discover -s tests -v
streamlit run app/main.py
```

画面にはPython、依存ライブラリ、SQLite FTS5、Tesseract、Ollamaの状態を表示します。画面起動時に `No module named 'backend'` が表示された場合は、実行中のStreamlitを停止してから、上記コマンドで再起動してください。PDFや書籍データを外部へ送信する機能はありません。Streamlitは標準設定で `127.0.0.1` のみで待ち受け、利用統計の送信を無効にします。

## 開発ステップ

1. 開発環境確認：完了
2. PDF登録・テキスト抽出：実装済み
3. ページ単位OCRと確認：実装済み（実際の医学書籍でのOCR品質は未検証）
4. 検索：文字列検索を実装済み。意味検索・章分野フィルターは未実装
5. Ollamaによる根拠付き回答：実装済み（実書籍での回答品質は未検証）
6. 国家試験解説とExcel出力：4択1問ずつの初期版を実装。実問題での検証では品質・速度とも実用目標に未達。一括取込は未実装
